# 待处理、目录同步与合集（开发版）

[English](../en/library-organization.md)

这些功能尚未发布，不改变原图位置；只有用户明确执行下载、隔离、恢复等操作时才写入图片文件。

## 待处理

原“未识别文件夹”升级为“待处理”。扫描预览没有应用的文件夹也会保留，关闭窗口或重启不会丢失待确认项目。可以搜索路径、候选作者名字或 ID，并筛选以下状态：

- 无识别线索。
- 待查询 / 无有效结果，包括关闭联网识别的目录。
- 查询失败。
- 作者证据冲突，不能按多数样本自动归属。
- 已识别待确认。

目录不可用、待复查是额外标记。打开“识别证据”可以查看候选作者、依据、PID、样本原图、每次查询结果和处理时间；作者及作品按钮打开对应 Pixiv 页面。

“重试失败项”只处理失败目录中的失败样本；“重新核实”重新检查当前目录。“增加取样”每次最多增加 5 个不同 PID，每个目录累计最多 30 个。样本从不同位置分散选取并按 PID 去重；保持请求间隔，连续三次请求失败停止当前批次。其他目录不会被定向重试遍历。

确认归属前再次核对目录元数据、建议版本和艺术家数据库。结果过期时先重新核实；应用一个目录后，其他目录若因数据库变化提示过期，也需重新核实。手动指定和排除仍然可用。文件变化只标记待复查，不自动联网识别。

## 目录同步

设置 → 常规的“自动同步图库目录”默认开启，仅在程序运行时监听下载目录。底栏可临时暂停，也会显示同步中、待重试、监听降级和不可用目录。

- 短时间事件合并 1 秒，持续变化最多等待 5 秒形成一批；同时只有一个同步任务。
- 新增、修改、删除和移动仅检查受影响目录；局部结果与当前索引合并，不删除未检查目录的记录。
- 写入中的文件间隔 1 秒检查大小和修改时间；未稳定或读取失败时保留旧记录，稍后重试。
- 启动时异步核对关闭期间的变化，每 15 分钟补查文件元数据；未变图片复用尺寸缓存。
- 监听失败或通知溢出触发补查；不可用目录每 60 秒尝试重连。离线、权限错误或枚举不完整不能作为删除证据。
- 忽略隔离区、应用数据、备份、缓存、临时下载文件和越出图库根目录的目录链接。
- 扫描、清理及备份恢复期间不提交同步结果；恢复后的旧任务不能覆盖新数据。

目录同步不替代艺术家识别，也不会自动检查 Pixiv 更新或下载。恢复备份后重新加载当前状态，并可重新核对本地元数据。

## 合集

图库侧栏提供“智能合集”和“项目合集”，沿用图库网格、详情及六种排序。

**智能合集**保存创建时的筛选与排序，按完整图库动态计算。临时搜索或调整条件不会覆盖保存规则，使用“更新合集条件”明确保存。新增“不含已用过”和“最近加入图库”条件，天数默认 30。首次加入时间跟随图片身份；升级前的图片没有可靠时间时保留为空，不把升级日期当成加入日期。时间条件在前台恢复及每分钟刷新。

**项目合集**通过多选图片后“加入项目”维护，同一张图可加入多个项目，同一项目不重复添加。删除合集、移出成员和撤销只影响组织关系，不移动或删除原图。移动后的引用跟随稳定身份；缺失、离线或隔离成员保留，并可展开不可用成员列表查看原因。

“拖出合集原图”使用整个合集的可用原图，忽略临时筛选。智能合集采用已保存的规则，项目采用当前图库排序；显示可拖出与不可用数量。超过 1,000 张不会截断，请通过网格多选后分批拖出。原图在核查之后又被移动或删除时，原生拖出会报错，刷新后重试。

合集写入可撤销，备份新增“合集”类别。跨存储恢复只按唯一且验证一致的内容关联，歧义成员保留为待匹配。设置重置、窗口布局重置和重建索引不会删除合集。

## 存储与开发验证

- `scan_review.sqlite3`：应用数据目录内，按艺术家数据库及标注存储数据集隔离。旧缓存只迁移路径与数量，不编造识别依据。
- `<索引名>.collections.sqlite3`：与当前图库索引相邻，成员引用 `store_id + image_id`，不使用路径作为身份。
- 标注 SQLite 增加可空 `first_seen_ns`；旧记录保留空值。合集成员添加时校验内容并保存指纹供移动关联。
- 备份 ZIP v2 增加 `collections.sqlite3`，仍支持读取 v1。待处理队列不是备份类别，详见[备份说明](backup-recovery.md)。

新增 IPC：`scan.review.list/detail/retry/sample/apply`、`library.sync`、`collections.list/create/update/delete/members.add/members.remove`。合集列表默认只返回摘要，指定 `id` 加载成员；智能合集可传 `image_ids` 核对可用原图。`library.sync` 返回增删改记录、不可用目录、待重试路径及提交前后索引摘要。

Rust `notify` 常驻监听；`configure_directory_sync`、`poll_directory_sync`、`acknowledge_directory_sync` 管理代次、事件队列和确认。Python 提交使用现有恢复协调锁；JSON 索引是可重建缓存，用户标注和合集不是缓存。

验证命令：`python -m pytest`、`cargo test --lib`、`npm run lint`、`npm run build`、`npx playwright test --workers=2`。`python scripts/benchmark_library_sync.py` 在独立临时目录生成三万张测试图片，检查完整补查、局部合并、三万成员的备份和撤销。冻结后端使用 `scripts/verify_annotation_storage.py <worker.exe>` 验证新增接口。

原生 Windows 深层目录事件和原图拖出载荷有自动测试。安装版拖入 PureRef、真实磁盘拔插及特定网络盘的监听行为仍需人工验收，不能用浏览器 mock 代替。
